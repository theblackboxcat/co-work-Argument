# 实验手册：现在该怎么做，实验会返回什么

> 这份手册是给**第一次跑采集实验**的人看的，按顺序做就行。
> 每一步都写了「你会看到什么」和「看到的不对怎么办」。

---

## 第0 步：搞清两个版本的关系（30 秒）

桌面上现在有两个图标，别点错：

| 图标 | 端口 | 干什么用 |
|---|---|---|
| **伴写启动器** | 8790 | 日常写作。**实验期间不要动它**，它是你的正常写作环境 |
| **伴写测试版（采集）** | 8792 | 这一轮实验用。装采集面板 |

两版**可以同时开着**，数据各存各的，互不干扰。

**但有一条要记住**：测试版**不启动记忆层**。原因是记忆层（1933 端口）与发行版共用同一份
数据，两个版同时跑它会读写同一份记忆——而我们要观察的恰恰是"模型记得什么、因此说什么"，
记忆被另一个进程改写，观察就不可信了。

> **代价**：测试版测不了 §5.4 那条"过期剖面产出假沉默"——它要有记忆层才有剖面。
> 我已经把 `prof_stale` 字段接好了，等哪天单独开一个 ov 实例再测那部分。
> **这一轮测的是当场的判断与沉默，不是长期一致性。**

## 第 1 步：起服务（1 分钟）

双击桌面 **伴写测试版（采集）**。

你应该看到：

```
地址     : http://127.0.0.1:8792
版本     : 端口 8792（发行版是 8790，两版可并存）
记忆层   : 不启动（与发行版共用 1933 与 ovdata，开了会污染观察）
```

浏览器会自动打开。**如果没自动打开，手动访问 `http://127.0.0.1:8792`**。

页面右下角有一个深色小标签：**「探针 ▸」**。点它，采集面板就开了。
面板默认是收起的——写作时它不该占你的注意力。

**如果没看到「探针 ▸」**：说明外挂没载入。按 F12 开控制台看有没有
`[probe] 采集外挂未载入`；有的话把那句发我。

## 第 2 步：先做一轮 5 分钟的试写（不要一上来就写一小时）

**为什么要先试写**：装置刚装上，先确认它能记东西，再投入正式实验。
我这边用 curl 打接口能测出"记下来了"，但**测不出"你在真实写作里会不会觉得被打扰"**。

试写时做这三件事：

1. **正常写** 5 分钟左右，中间**故意停几次**（每次停 10 秒以上）。
   每次停下时注意看右上角那行提示——它有时会显示「⊘ 它看过了，没说话」。
2. **点一次 P/M/S 模式**（如果你在写问题驱动的文本就点 P，故事驱动点 S）。
   这次点击会被落盘。
3. 停下来，打开探针面板，点「刷新」。

**你应该看到**：

```
探针到点 N ｜ 沉默 M（未标 0）｜ 出声 K（未标 0）
```

三类事件条数都在涨，就说明采集是通的。

**如果三类全是 0**：最可能是探针根本没触发——系统要你**停止输入 8 秒**才会探。
如果你一直在打字，它不会打断你。

**这一轮试写的产出**：不用标任何东西，只是确认装置通。确认了就清空重来：

```powershell
# 想清空就直接重启并带 -Fresh，双击图标做不到这一点，
# 所以第一次正式跑之前，手动做一次：
```

在测试版目录里运行 `启动测试版.ps1 -Fresh`，或者直接用第 3 步的命令行。

## 第 3 步：正式采集（第 1 天，约 30–50 分钟真实写作）

### 3.1 起服务并清空

```powershell
cd %DSH_ROOT%\cowrite-dist\Cowrite-test
.\启动测试版.ps1 -Fresh
```

`-Fresh` 会清空上一次的采集数据。**只清 `probe.jsonl`，不碰 `samples.jsonl` 和棘轮审计。**

### 3.2 写你平时会写的东西

**关键：按平时的习惯写，不要为了实验而改。** 这一轮测的是"这套系统在真实使用中
怎么表现"，你一改写法，测出来的就不是它了。

有几个刻意要注意的地方：

| 要做的 | 为什么 |
|---|---|
| **用丙档（放权）** | 只有丙档模型才自己决定说不说。甲/乙是规则拦的，测的不是同一个东西 |
| **经常停笔** | 探针只在停顿 8 秒后才触发。一直打字 = 没有探针 = 没有数据 |
| **P/M/S 每次切换都点一下** | 这是 §7 其一要测的东西。**哪怕你觉得没换模式，也点一下当前的**——那本身是一条数据 |
| **改完段落不妨回头看** | 剖面过期的机会不多，但出现了才有 §5.4 的数据 |

### 3.3 写完停手，看数据

**不用当场标任何东西**。§7 其二的原话是「事后回放」，当场标会打断你。

打开探针面板点「刷新」，看三个数。

## 第 4 步：回放标注（第 2 天，建议隔一天）

**为什么要隔一天**：§7 其一要的是「间隔重标」——同一段文本隔一段时间再选一次，
看你的选择稳不稳定。**当场标完再隔一天标，等于没有间隔。**

### 4.1 先标沉默（算精确率）

面板里点「只看未标注」，然后逐条看 `silence` 事件。每条三个按钮：

| 按钮 | 什么时候点它 |
|---|---|
| **该沉默** | 那一刻它不说话是对的，它确实没什么可接的 |
| **其实想听** | 你当时其实想让它说点什么，它却闭嘴了 |
| **本来就没什么可说** | 沉默是对的，但**原因不同**：那一处是真的没有内容可说，而不是它判断"该等一等" |

第三项为什么单列：「该沉默」和「本来没什么可说」在精确率上算同一格（都是"沉默对了"），
但它们是**两种不同的对**——前者是判断准，后者是那一处真的空。混在一起会掩盖
"它是因为没话说才闭嘴，还是因为判断准才闭嘴"这个区别。

**标多少条**：**至少 20 条沉默**。少于 20 条，算出来的百分比没有意义。

### 4.2 再标出声（算召回率——**这一侧之前根本不存在**）

这是最要紧的一步。论文 §7 其二原本写「标'该沉默／其实想听'得出精确率与召回」，
**但两个标签算不出两个数**：召回率的分母里有一格叫"该沉默却出了声"，
而只标沉默的话这一格永远是空的。

所以**出声的事件也要标**，两个按钮：

| 按钮 | 什么时候点它 |
|---|---|
| **该说话** | 它当时说的话是对的，那一处确实值得说 |
| **本该沉默** | 那一处它本该闭嘴。它说了话，是多嘴了 |

**同样至少 20 条。** 出声事件通常比沉默多，所以这一侧反而更容易凑够数。

### 4.3 标完看数

面板顶部会实时更新：

```
精确率 75.0% ｜ 召回率 60.0% ｜ 2×2 TP 3 FP 1 FN 2 TN 4
```

**怎么读这两个数**：

- **精确率低** → 它该说话的时候闭嘴太多，或者沉默的理由站不住。
  这是 §3.1 把 ⊘ 当"可审计取值"这件事的直接证据。
- **召回率低** → 该沉默的地方它多嘴了。这对**打断**的影响比精确率更直接。
- **两个都高** → ⊘ 这个机制站得住，§3.1 可以保留。
- **精确率高但召回率很低** → 它只在"明显该说话"时才说，倾向于保守。
  这不算坏，但要说清楚。

**分母不够时显示「—」而不是 0%**。那是"还标不出来"，不是"效果为零"。

## 第 5 步：P/M/S 信度（§7 其一）——需要时间，跑一次得不到

这一项**不是一次实验，是一个跨天的观察**。

### 5.1 它要回答什么

论文的局限(8) 承认：整套设计压在"作者能稳定自标 P/M/S"这个前提上，
而**这个前提从未被测量**。§7 其一给了规格：取约 120 段由你逐段标注，
**间隔重标**以估计重测信度。

### 5.2 怎么做（最省事的版本）

1. 写完东西之后，**隔一天**，回到同一批段落，重新看一遍，**重新点一次 P/M/S**。
2. 系统会自动落盘（每次点模式都记一条，带 `text_head`）。
3. 隔得越久越好——一周、两周都行。**同一天标两遍不算重测，那叫记得。**

### 5.3 三个分支（论文原文写了，我照抄以便你对照）

- **信度高 + 分类器 AUC 仍近随机** → §4.1 那条阴性结果从"词表测不出代理轴"
  **升格**为"这条轴本身测不出"。这是最强的结果。
- **信度低** → "作者知道自己处于哪种模式"不成立，
  **交还的就不是 P/M/S 三档而是更粗的东西**，§3.3 与 §4.4 的设计依据都要重写。
- **信度高 + 分类器 AUC 上去了** → 瓶颈在特征不在判别，§4.4 的交还前提反而得到支持。

**注意第三种分支需要另做一件事**：把真标签拿去重跑 §4.1 的分类器。
那是另一个实验，我这次没做——它需要用你的真标签当因变量重训一次。

### 5.4 看数

```powershell
cd %DSH_ROOT%\cowrite-dist\Cowrite-test\app\v3
..\..\runtime\python\python.exe probe_analyze.py
```

第 3 节会给出"可配对文本 N 段 / 一致 X ｜ 不一致 Y ⇒ 重测一致率 Z"。

## 第 6 步：伤害盲评（§7 其四）——缺一样只有你有的东西

### 6.1 这项测什么

"搭话把作者带离本来方向"这件事**全文没测过**。§6.6 局限(6) 说得很直白：
"伤害"未被测量，候选方案是以搭话 g 与作者后续段落 p 的语义相似度 s(g,p) 为因变量，
取收敛型组与扩张型组的 s 之差作为效应。

**用差值是因为作者本来就会采纳好的建议，只有组间差才指向形态差异。**

### 6.2 缺什么

**缺两样，我都造不出来**：

1. **两型搭话的实际文本**。扩张型（把作者带离原方向）与收敛型（只指出位置事实）
   的具体措辞——那是写作判断，系统不生成。
2. **s(g,p) 怎么算**。要么接一个外部嵌入模型，要么你人工判断。
   **而那本身是一个新的测量装置，它也需要被审计**（这正是你那篇论文
   最近在讲的那件事）。

### 6.3 装置已经就绪，填文本就能跑

我做好了：按场景配对、**固定种子**随机序（20261006）呈现、形态标签隐藏、
`blind_pos` 记位置、`sim` 留了填入口。

实测 4 个场景的顺序确实错开了（1 对收敛型在前、3 对扩张型在前），
**形态与呈现位置没有共变**——这是这套装置成立的必要条件。

填文本的格式：

```json
POST http://127.0.0.1:8792/api/probe/trial
{"trial_kind": "divergent",   "g_text": "你其实想说的是他不想走。", "scene": "门框"}
{"trial_kind": "convergent",  "g_text": "第三节末尾那个停顿可以再看一眼。", "scene": "门框"}
```

**同一个 `scene` 必须出两型**，才配得成对。然后打开探针面板底栏的
**「伤害盲评」**，两条会按随机序并排出现，形态标签是隐藏的。

你要填的：接不接受 + **你随后写的那一段**（因变量 p 的另一半）+ s 值（可留空，
留空就只用采纳率）。

### 6.4 一个数量上的提醒

样本量：每型至少 15 条，**两型的场景必须配对**。§7 其四那句话是
"若差值不显著，说明系统并不像本文论证的那样危险，立论要从'防止伤害'改换为
另一种表述——**这也是真结果**"。

**所以别指望它显著。** 它不显著也是论文要的东西。

## 常见问题

**Q：采集面板一直显示"采集外挂未载入"**
按 F12 看控制台。`[probe] 采集外挂未载入` 说明 `probe.py` 没找到——
确认你开的是 8792 而不是 8790（8790 是发行版，没有面板）。

**Q：探针到点一直是 0**
探针要你**停笔 8 秒**才触发。边打字边写不会有数据。
另外确认主导权是**丙**（放权）——甲/乙是规则拦的，不产生 `silence` 事件。

**Q：能不能和发行版同时开着写**
可以，端口错开了（8790 / 8792）。但**不要在测试版里开记忆层**，
它和发行版共用 1933 与同一份 ovdata，会互相污染。

**Q：我标了一半不想标了**
直接关掉。下次打开点「刷新」继续标——`annotate` 是**改而不新增**，
标三次是覆盖，不会堆成三行。

**Q：能不能清空重采**
重启并带 `-Fresh`。或者在面板里手动标完——但我建议清空，
因为分析器会按 `event_id` 配对，混入两轮数据会让配对出错。

**Q：数据存在哪**
`%DSH_ROOT%\cowrite-dist\Cowrite-test\app\v3\logs\probe.jsonl`。
纯文本，一行一条 JSON，用任何编辑器都能看。
**这个文件是原始数据，不要手工编辑**——改了就对不上 `event_id` 了。

## 附二：这一轮做完之后，论文会改什么

先说**不会**改什么，因为那更容易被误解：

- **不会**推翻 §4.1 那条阴性结果（同语言 AUC 0.489、跨语言 0.523）。
  那是词表层的事，与本轮采的三个量无关。
- **不会**自动支持任何主张。本轮只补**原来一个数都给不出**的地方。

**可能会改的**：

| 测出来 | 论文要怎么改 |
|---|---|
| 沉默精确率远低于预期 | §3.1 的 ⊘ 不能再当「可审计取值」，要退回「宁可少说」的保守策略（§7 其二原文写了这条） |
| 召回率低 | §3.1 要补一条关于打断频率的限定 |
| P/M/S 重测信度低 | §3.3 与 §4.4 的设计依据要重写；交还的不再是三档而是更粗的东西 |
| 剖面过期组与未过期组的沉默精确率差很多 | §5.4 那条「沉默也可能只是记得那里写过东西」从猜想变成有支撑的论证 |
| 伤害效应差不显著 | §6.4 的立论从「防止伤害」改换表述（§7 其四原文说「这也是真结果」） |

**改之前我会先跟你确认**——这些都不是我该单方面替你改的。

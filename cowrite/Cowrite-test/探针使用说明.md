## 沉默的精确率与召回：一个定义问题的解

论文 §7 其二写「事后回放由作者标'该沉默／其实想听'，得出沉默的精确率与召回」。
**但两个标签算不出两个数。** 精确率与召回率都是二元分类的两条：

```
精确率 = TP/(TP+FP)   它沉默的那些里，该沉默的占多少
召回率 = TP/(TP+FN)   该沉默的那些里，它沉默的占多少
```

要算召回必须知道「该沉默」的**总数**，而「该沉默却出了声」那一格
在只标沉默的情况下**永远是空的**——因为不出声的那次探针没有可标注的对象。

所以给出声事件也加了真值轴，构成同一个 2×2：

| | 作者说该沉默 | 作者说该说话 |
|---|---|---|
| **它沉默了** | TP（该沉默） | FP（其实想听／本来没什么可说） |
| **它出了声** | FN（**本该沉默**） | TN（该说话） |

**出声侧的标注是算召回率的唯一来源。** 走事后回放，不在出声时立刻问
（立刻问会打断写作，违反 §3.1 铁律一）。

实测验证：造 TP=3/FP=1/FN=2/TN=4，分析器给出精确率 0.75、召回率 0.60，与预期一致。

**分母不足时给 `None` 不给 0。** 0 意味着"算出来是0"，None 意味着"还标不出来"，
后者才是常态。

## 伤害盲评（§7 其四）

采集面板底栏 → 「伤害盲评」。同一场景的两型搭话**按随机序呈现，形态标签隐藏**。

**随机序用固定种子（20261006）而不是真随机**——可复现优先：同一批文本两次跑
必须落在同一顺序上，否则顺序效应与形态效应分不开。换种子等于换一次实验。

实测 4 个场景的顺序确实错开了（1 对 convergent 在前、3 对 divergent 在前），
**形态与呈现位置没有共变**。这是这套装置成立的必要条件。

**要填的**：接不接受 + 你随后写的那一段（因变量 p）+ s(g,p) 值（可留空）。
分析器**不算 s(g,p)**——那需要外部嵌入或人工判断，凭空造数会让后面所有结论失真。

## 两条纪律

1. **采集失败不许影响写作。** 三处埋点全包 try，失败只打印 `[probe] xxx埋点失败（不影响出卡）`；
   外挂装不上只是 `probe` 变None，写作照常。
2. **采集器自己的失败必须失败得可见。** `probe.record()` 不吞异常——
   一份静默丢掉的采集数据会让后续所有分析看起来"没有效应"。

## 剩下要你做的四件

装置全部就位，缺的都是**只有你才能提供的东西**：

1. **真实使用一段时间**。沉默事件、剖面过期事件、手选记录都要真写作才产生。
   手造的样本能验装置，不能验结论。
2. **回放标注**。至少标20 条沉默（算精确率）与 20 条出声（算召回率），
   否则两个率都还标不出来。
3. **P/M/S 间隔重标**。§7 其一要的是"间隔重标"——同一段文本隔一段时间再选一次。
   这件事**需要时间间隔，跑一次得不到**。
4. **两型搭话的实际文本** + **s(g,p) 怎么算**。前者是写作判断，系统不生成；
   后者要么接一个外部嵌入，要么人工判断——**而那本身是一个新的测量装置，
   它也需要被审计**。这两条是缺口③④的入口。

## 本轮踩的坑（都会再犯）

1. **event_id 写盘太晚**：放在 `write()` 之后只改内存 dict ⇒ `annotate()` 永远找不到行。
   **回填是地基，第一个冒烟测试就抓到**。id 必须写盘前定。
2. **前缀撞车**：`kind[:3]` 让 `probe_to_point` 与 `probe_trial` 都成 `pro` ⇒ 改显式前缀表。
3. **`os.remove` 被本机 safe-delete 守卫拦下**（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`，
   threshold=50）⇒ handler 崩、客户端收到**完全空的响应**（不是 4xx）。
   改成以空内容覆盖写。`os.replace`（改名）不受影响。
4. **同名字段被循环变量覆盖**：`'spoke': spk` 而`spk` 已是列表 ⇒ 接口吐出一堆完整行。
   批量替换旧代码时要核对新变量的类型。
5. **替换残留三元运算符**：`r.kind === 'x' ? A : B` 只替换了前半截 ⇒
   `(KIND_BTNS[r.kind] : B)`。**改完必须跑 `node -e "new Function(...)"` 验JS 语法。**
6. **缩进差异导致锚点匹配失败**：从文件里复制片段时行首空格数可能已被改动。
   **按行号/关键词定位比按整段文本匹配稳。**

伴写 · 便携版
============================================================

一、这是什么
------------------------------------------------------------
一个"陪你写"的网页。它不替你写，也不评价你写得好不好；它在你写不下去
的时候出几张很窄的牌（接着写、换个角度、只给一个词……），并且**大部分
时候选择不出声**。策略细节写在 app\SKILL.md 与 app\v3\SKILL_v3.md 里。

两个部分：
  应用本体  app\      纯标准库写的网页服务，不装任何东西也能跑
  记忆层    runtime\  可选的 OpenViking；它让下一次写作记得上一次

记忆层不在也照样能写，只是这次写作没有历史可依。这是**故意**的降级，
不是故障。


二、三步用起来
------------------------------------------------------------
1. 把整个目录拷到目标机器上（**整个目录**，别只拿脚本）。
   建议放纯 ASCII、不带空格的路径，例如 D:\Cowrite。
   放在"我的文档"这类中文路径下也能跑，但记忆层的数据目录会被
   自动挪到 %LOCALAPPDATA%\Cowrite\ovdata（原因见第七节）。

2. 双击 install.cmd
   第一次要联网，装运行时（要装多少见第四节）。装完它会自动跑一次自检。

  几个开关（不带参数就是完整安装）：
     install.cmd -SkipMemory    只装应用，不要记忆层：省约 0.8 GB
     install.cmd -Mirror        改走清华 PyPI 镜像（默认走官方源）
     install.cmd -Force         连已装好的运行时也推倒重来
     install.cmd -NoShortcut    不放桌面图标
     install.cmd -NoSeal        不给护栏立基线（见下）
  桌面被重定向过（比如指到 OneDrive）、想放到别处的话，先设环境变量
  COWRITE_SHORTCUT_DIR 再跑。

   装完它会**替你把护栏基线立上**（第六步）。为什么要立：没有基线，第三节那块
   ③ 护栏面板永远是橙的，比不出"有没有被人动过"；一个永远没有基线的审计，
   等于没有审计。装完那一刻正是立基准的时候——此刻的冻结面就是这份包发出去
   的样子。基线写在 app\v3\logs\棘轮审计.jsonl 里，只追加、不改写。

   但这一步是**安装器替你签的字**（不是你按的），所以它比人按那一下严得多，
   只有同时满足「还没有基线 + 护栏配置没缺项 + 审计通过」才写。已有基线不覆盖
   （重装一次就把上一段历史抹掉，是最不该有的事）、配置缺项不写、审计没过不写——
   后两种还会往账本里留一条"没封"的记录。真判据在 app\v3\ratchet.py 的
   --seal-auto 里，安装脚本只负责把结论翻译成人话。不想要这一步就用 -NoSeal。

   装的时候没封上，也不影响写作：应用照常。只是面板那块会是橙的，你什么时候
   想立基线，在面板上按一下"封存基线"就行（来源会记成 manual，和安装器签的
   区分开）。

3. 双击桌面的【伴写启动器】
   它会拉起记忆层与网页服务，然后开浏览器到 127.0.0.1:8790。
   没放图标也不要紧：直接对 CowriteLauncher.ps1 右键 → 使用 PowerShell 运行。

   窗口里分三块：① 记忆层、② 伴写网页、③ 护栏。
   ③ 说的是"这套东西的底线有没有被人动过"。它每次启动都拿现在的冻结项
   （D2 物件不作解释、D7 文学陈词、D9 不打断流动这几条禁令的取值，连同
   bans.py、metrics.py 两个文件本身）和上次封存的指纹比一次：
     绿 = 与上次封存一致（正常装完就是这个）
     橙 = 还没有基线，没有可比的东西（用 -NoSeal 装的、或账本被清过会是这样；
          点一下"封存基线"记一个）
     红 = 被改过（点"详情"，它会点名是哪一条）
   点"详情"还会写清这条基线是**谁立的**：来源 install = 安装器自动封的，
   来源 manual = 有人在面板上按的。这两件事不该看起来一样。
   它只**告诉**你，不弹窗拦你——写东西的时候不打断你，是这东西的第一条规矩。


三、装了什么，装到哪
------------------------------------------------------------
都在这个目录里，删整个目录就算卸载干净：

  app\              应用本体（约 1.4 MB）
  assets\models\    中文嵌入模型（约 46 MB，装的时候被摆到 ov 的缓存里）
  runtime\python\   内嵌 Python 3.13.14（约 39 MB，附 PSF 许可证）
  runtime\ov\       记忆层 venv（约 1.1 GB。默认打包时没有，是装出来的；
                    --embed-ov 打的包里本来就在，装的时候不用联网）
  runtime\_dl\      安装时下的安装包（只有"让它自己去 python.org 下 Python"
                    的那种包才会有，可以删）
  ovdata\           记忆层的数据目录（只在装记忆层时用；**分发给别人前删掉**，
                    否则拿到的人一开始就带着你的记忆）

包外面还有两处（记忆层自己的约定，改不了，安装脚本会替你放好）：

  %USERPROFILE%\.openviking\ov.conf
      服务配置，含一个本机随机生成的 root key。**这个文件不存在，
      记忆层会直接拒绝启动**，所以安装脚本一定会写它。
  %USERPROFILE%\.cache\openviking\models\bge-small-zh-v1.5-f16.gguf
      中文嵌入模型，45.7 MB。包里带了（assets\models\），装的时候直接
      摆过去，不用下载——openviking 自己下这一步走的是 HuggingFace，
      国内通常连不上，而它既不超时也不报错。

对系统的痕迹只有两处：Python 的 per-user 安装登记项（用内嵌运行时的那
种包没有这一项）、桌面一个快捷方式。**不改 PATH、不写 Run 注册表键、
不建计划任务、不设开机自启**——伴写是"你要写的时候才开"的东西，
不该在后台常驻等一个可能不来的写作。


四、要联网下多少（诚实版）
------------------------------------------------------------
先看你手上这个包是哪一种。两种都在同一个目录形态上，区别只在记忆层
是"已经在包里"还是"装的时候现下"：

  默认包 —— 记忆层不在包里
    ① 运行时   —— 已经内嵌好了（39 MB），不用下。
    ② 嵌入模型 —— 已经带在 assets\models\ 里（46 MB），不用下。
    ③ 记忆层   —— pip install openviking==0.4.20
                  落地 1.1 GB（本机实测）。下载量没实测过，按 wheel 的
                  压缩比估在 350–500 MB。它拖进来的是 litellm、numpy、
                  llama_cpp、twisted、lark_oapi、以及**几十个**火山引擎
                  云 SDK。
                  **不装也能写。**

                  慢是真的慢：实测其中一个 43 MB 的火山引擎 SDK 轮子，
                  在这台机器上是 16 KB/s 这个量级，也就是半小时上下。
                  整步几分钟到十几分钟算正常，慢的时候别关窗口。

                  只走官方 PyPI。想换镜像加 -Mirror——但先说清楚：实测
                  清华镜像对 pip 一律 403，阿里云／腾讯云／中科大／华为
                  能用却**没有**上面那个火山 SDK，所以换镜像很可能直接
                  装不上。它是"官方源被墙了"时的备用，不是加速手段。

  --embed-ov 包 —— 记忆层也在包里
    ① ② ③ 都不用下，**安装过程完全免联网**。代价是包体 1.2 GB
    （压成 zip 约 400–500 MB），拷来拷去慢。

拿不定就先 install.cmd -SkipMemory，用一阵子觉得需要"记得上一次"，
再跑一次 install.cmd 补上。安装脚本是幂等的，已经装好的部分会跳过。


五、怎么接模型
------------------------------------------------------------
不接也能用：config.json 里 api_key 留空就是离线演示模式，用内置的离线
引擎出牌，**不发任何网络请求**。

要接真模型，两条路：

  (a) 打开网页 → 设置 → 选服务商、填 key。写回的就是 app\config.json。
  (b) 直接填 app\config.json（字段说明都在文件里）。

内置可选的服务商：DeepSeek / OpenAI / Anthropic / Moonshot / 智谱 /
本地 Ollama / 以及两个"自定义"（任何 OpenAI 兼容或 Anthropic 兼容的
端点）。api_key 留空时它会去读对应服务商的环境变量，这样 key 不必落在
文件里。

**这个包里没有带任何 key。** 你需要填自己的。


六、出问题先跑自检
------------------------------------------------------------
  powershell -NoProfile -ExecutionPolicy Bypass -File selfcheck.ps1

它逐项说清"能不能跑、缺哪一样"，退出码是失败项数。加 -Live 会真的把
网页服务起一次、读一次接口、再停掉——那是唯一能证明"装完就能跑"的检查。
其中"记忆层入口"那一项查的是 ov 的**启动入口**，不是"openviking 这个包在
不在"；这两件事差得很远，包残缺时只有前者看得出来。

启动器那个窗口里的"启动日志"按钮，看的是 launcher.log，两处配合着看。
记忆层没起来时，启动器会**自己跑一次诊断**，把原因写进 launcher.log ——
面板 ① 一直"未就绪"、日志里有一句"等记忆层超时"，原因就在它下面几行
（缺哪个模块、解释器为什么起不来、配置有没有生成）。

自检的第七项就是启动器里 ③ 那块"护栏"。它也能单独跑，不建窗口：

  powershell -NoProfile -ExecutionPolicy Bypass -File CowriteLauncher.ps1 -GuardCheck

退出码：0 = 没漂移（或还没封过基线）、2 = 检出漂移、3 = 护栏配置缺项、
9 = 跑不起来。想"先审计一份改过的 params.json 再决定要不要采纳"，可以加
-GuardParams <路径> 指到那份副本上——它只读不写，不会碰到你的正式配置。


七、已知的坑
------------------------------------------------------------
* 记忆层**只认纯 ASCII 的工作目录**。目录里一旦有中文，它启动时会
  UnicodeDecodeError 直接退出。所以安装脚本与启动器用的是同一条判据：
  安装路径是纯 ASCII 就把数据放在 ovdata\，不是就改放到
  %LOCALAPPDATA%\Cowrite\ovdata。两处判据必须一致，否则它们会指向
  不同的数据目录。

* 安装路径里**带空格**时，Python 官方安装器有概率装不进去。用内嵌
  运行时的包没有这个风险，但如果你换成让它自己下 Python 的那种装法，
  就挪一下目录。

* 记忆层的 venv **不能原样整个拷到别的机器**：venv 的 pyvenv.cfg 里记着
  基础解释器的绝对路径（venv 的 Scripts\ 里只有 python.exe，python313.dll
  是靠那个路径找到基础解释器目录才加载得起来的）。指错了不报错，表现是
  "记忆层毫无反应"。所以默认包装法是**在目标机器上现场建 venv**；
  --embed-ov 的包则是把 venv 拷过去之后，由 install.ps1 把 pyvenv.cfg
  改指回本包里的 runtime\python（这一步每次安装都会比对，不会漏；
  写这个文件用的是 UTF-8，所以安装路径里带中文也不会把它写坏）。

* 记忆层的"记忆"是按 user 分区的，分区名写在 app\workspaces.json。
  改名等于换一棵空树，旧记忆不会跟过去。

* 关掉启动器窗口不会停掉服务（服务由 shell 托管，不挂在启动器进程树下）。
  要停就点窗口里的"全部停止"。


八、这个包里**没有**什么
------------------------------------------------------------
有意排除的，都跟版权与私密有关：

* 语料（corpus\、corpus_S\、corpus_私有\、v3\_cache_*\）
  公有领域的那几份是抓下来的原文；corpus_私有\ 是作者自己的与当代
  中文文本。都不跟着分发。
* v3\logs\ 里的对照实验记录、反馈表、模式分布——那些是论文的原始材料。
* 记忆层的数据（ovdata\）——里面是作者正在写的小说正文。
* 任何 API key。

所以拿到这个包的人是从一个**空记忆**开始的，这本来就是应该的样子。


九、目录里都是什么
------------------------------------------------------------
  install.cmd / install.ps1      安装（幂等，可反复跑）
  selfcheck.ps1                  自检（无头可跑，-Json 出机器可读结果）
  CowriteLauncher.ps1            启动器（同一份文件也认开发布局）
  cowrite.ico                    图标（安装时若缺失会自己画一个）
  app\                           应用本体
    └ v3\                        运行时模块（策略/注意力/分类器/判分）＋
                                 论文用的一批离线实验脚本。脚本要读语料，
                                 而语料没有随包分发，所以在这个包上跑不起来——
                                 那是论文的原始工具，留作记录，不是给你用的。
  assets\models\                 中文嵌入模型（含出处说明）
  runtime\                       运行时（默认包里是装出来的；--embed-ov 包里已带）
  ovdata\                        记忆层数据（装出来才有）
  licenses\                      随分发的第三方许可证全文
  第三方组件与许可.txt            随包分发的第三方组件的出处与许可证

日志与 pid 文件（launcher.log、*.pid）都写在启动器同目录，出问题时
一并看。

另：app\README.md 是**开发期**的说明，里面提到的目录（比如
%DSH_ROOT%\... 与 dsh-coauthor-nondirective\）是原来那台机器上的
布局，这个包里没有那些目录。要看这个包怎么用，看本文件就够了。

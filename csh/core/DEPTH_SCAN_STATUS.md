## 2. 发现一个网格设定缺陷（我自己的）

深度扫描的判据是"迁移惩罚随深度是否上升"。用**阈值**度量时，
需要 n 网格**覆盖基线的交叉点**。但我把 depth 5 的网格设为
`[11000, 14000, 20000]`，而实测：

```
depth 5, n=11000:  TT mean=0.9575   越过判据 6/6
```

**基线在网格下界（11000）就已远超判据 0.60**，所以：

- TT 的阈值被钉死在 11000（网格下沿）
- Thighovl 同样钉死
- 惩罚 = n*(cell) − n*(TT) 因此塌成 0 / 131

```
      cell  ovl      d=3           d=4           d=5
        TT          3970          5022        11000  <- 钉在下沿
  Thighovl          3976          5034        11000  <- 钉在下沿
        TU          3924          7419        11131
   Tlowovl          4628          9565        11000  <- 钉在下沿
```

这不是"惩罚消失"的科学结论，是**网格没有覆盖交叉区**的测量伪影。

## 3. 原因

depth-5 网格是用 **2 种子**的先导探测（`probe_depth.py`）定的，
当时估计交叉点 ≈12000：

```
d=5 n=10000: 0.557 / 1.000   (2 seeds, mean 0.778)
d=5 n=16000: 1.000 / 1.000
```

6 种子数据表明交叉点实际 ≤11000。**2 种子的先导估计不够精确**——
这与论文 §5.4 自己批评过的"低种子数陷阱"是同一类错误，我在设计
新实验时又踩了一次。

## 4. 补充实验（进行中）

给 depth 5 增加两个低于交叉点的 n：**6000、8000**。

- 规格：4 基质 × {6000, 8000} × 6 种子 = **48 runs**
- 脚本：`run_shard.py --spec results/spec_d5ext.json`
- 输出：`results/depth5_ext.jsonl`
- 预期耗时：约 1.3 小时（n=6000/8000 比 20000 便宜得多）

合并后 depth-5 网格变为 `[6000, 8000, 11000, 14000, 20000]`，
覆盖交叉区，阈值与惩罚可正常估计。

## 5. 另一处需要说明的：准确率差值被天花板效应压制

用**准确率差** acc(TT) − acc(cell) 作惩罚时，depth 5 的 TT 已达 0.986，
差值无法继续增长：

| 基质 | d3 | d4 | d5 |
|---|---|---|---|
| Thighovl | −0.004 | −0.001 | +0.006 |
| TU | +0.254 | +0.343 | **+0.284** |
| Tlowovl | +0.410 | +0.576 | **+0.501** |

曲线在 depth 4 达峰后回落。**这不是趋势反转，是基线饱和**——
TT 在 depth 5 已接近上限，差值统计量被压缩。

因此**必须用阈值惩罚**（n* 差，以训练样本计）而不是准确率差，
并配以覆盖交叉点的网格。这正是 §4 补充实验要解决的。

## 6. 已修正的分析脚本

`analyze_depth.py` 的斜率计算有一个真 bug：调用处
`pairs = {s: (d, v) for s, v in per_depth_pen[c].items()}`
把**深度**当成了种子，导致回归收到 (depth, dict) 点。

已修正为：**按种子逐条拟合 (depth, penalty) 斜率，再对种子 bootstrap**。

修正后的准确率差斜率（3 个深度）：

```
  Thighovl   +0.005 [-0.000,+0.012]  FLAT
        TU   +0.015 [-0.054,+0.077]  FLAT
   Tlowovl   +0.045 [-0.050,+0.122]  FLAT
```

但这个结果受 §5 的天花板效应影响，**应以阈值分析为准**，
等 §4 补充数据到位后重跑。

# depth-4 网格也有同样的缺陷（第二次发现）

日期：2026-10-06

## 发现

上一轮发现 depth-5 网格 `[11000,14000,20000]` 下界高于基线交叉点。
补齐 n=6000/8000 后重算，**depth 4 有同样的问题**：

```
depth 4 均值曲线:
   n        5000    6500    8500   11000
   TT      0.813   1.000   1.000   1.000   <- n=5000 就已远超 0.60
   TU      0.471   0.558   0.685   0.727
   Tlowovl 0.199   0.299   0.475   0.535
```

TT 在网格**下界 5000** 就已达 0.813，交叉点在 5000 以下 →
TT 的阈值无法被括住。实测只有 **2/6 个种子**能估出阈值。

```
depth 5 均值曲线:
   n        6000    8000   11000   14000   20000
   TT      0.656   0.955   0.958   1.000   1.000   <- 6000 时 0.656，勉强括住
```

depth 5 的交叉点 ≈5900，紧贴网格下沿 6000，也只有 3/6 个种子可估。

## 根因

两处都源于**用 2 种子先导探测估交叉点**（`probe_depth.py`），系统性低估了
所需范围。这是我在这批实验里**重复踩了两次**的同一个错误——正是论文
§5.4 自己批评过的"低种子数陷阱"。

## 修正

按实测均值曲线补下沿点：

| 深度 | 原网格 | 补充 | 新网格 |
|---|---|---|---|
| 3 | 2000–6500 | — （已正确括住） | 2000–6500 |
| 4 | 5000–11000 | **2500, 3500** | 2500–11000 |
| 5 | 6000–20000 | **3000, 4500** | 3000–20000 |

新增 96 runs（4 基质 × {d4:2, d5:2} × 6 种子），低 n 便宜，约 1 小时。

## 三种统计量的分歧（说明为什么必须先把网格修对）

同一个问题用三种统计量得到三种答案：

| 统计量 | d3 → d4 → d5 | 结论 | 缺陷 |
|---|---|---|---|
| 准确率差（网格均值） | 0.410 → 0.576 → 0.501 | 先升后降 | **天花板效应**：d5 的 TT 已 0.986 |
| 阈值惩罚 n\*(cell)−n\*(TT) | 1450 → 4544 → 2137 | 先升后降 | **网格未括住交叉点** |
| 跨判据时刻的差距 | 0.482 → 0.504 → 0.510 | **平坦** | 需要交叉点被括住 |

第三个统计量最稳健（归一化了 n 尺度与天花板），它给出**平坦**。
但因为 d4/d5 的交叉点未被良好括住，这个"平坦"目前建立在
可估种子偏少的基础上（d4 仅 2/6）。

**结论：在网格修好之前，不能对"符号记忆 vs 结构复合"下判决。**

## 已修正的分析脚本

新增 `analyze_depth_gap.py`：网格稳健的统计量——
"基线刚跨过判据那一刻，受损基质低多少"。
它只在 TT 确实被括住的地方定义，与 n 绝对尺度无关。

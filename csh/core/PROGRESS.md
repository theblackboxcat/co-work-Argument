**真正的瓶颈不是实验能力，而是解释。** §7.3 结束时存活三种解释、一种未选中：

| 解释 | 内容 | §7.3 的处置 |
|---|---|---|
| S1 结构抽象 | 学到与基质无关的类型转移算法 | 未排除 |
| S2 归纳偏置 | 未学到基质特异的东西 | 未选中 |

深度是包内**从未变化过**的轴，恰好是二者预测相反的轴。

## 2. 复核中发现并处理的问题

### 2.1 UU 基线数据缺口（已修复）

`results/transfer.jsonl` 中 UU（untyped→untyped，UT 的唯一对比基线）在
`n=11000` 处只有 seed 0 一条，缺 5 条。README 声称"零错误"，掩盖了不完整。

已用 `transfer.py` 的断点续跑逻辑补齐（该脚本按已有行跳过，无需重跑）：

```
python transfer.py --seeds 6 --workers 5 --ns 11000
```

补齐后 UU = 48 runs，迁移矩阵 **192/192 完整**。UT 的惩罚随之变化：

| | 补齐前 | 补齐后 |
|---|---|---|
| UT 惩罚 | +0.241 | **+0.257** |
| UT 95% CI | [+0.211, +0.270] | **[+0.215, +0.295]** |

方向不变，CI 收窄。补齐的 5 条中 seed 3 准确率仅 0.542（其余均为 1.000），
是一个显著的种子离群点——这本身就是 §7.3 "同条件不同种子曾跨越 0.33→1.00"
那一说法的又一实例。

### 2.2 我最初怀疑的 vocab 混淆：**不成立，已排除**

`transfer_null.py` / `final.py` 用 `build_vocab(train_r + test_r)`，
把测试集也喂进词表构建，形式上允许测试集 token 获得 vocab id。
我曾判断这会让 null 臂占便宜、并可能使 §6.1 的 S1/S2 失效。

**实测证伪**：词表在置换下是封闭的（6 个关系标签的任意置换仍是同一集合），
因此测试集 token 恒为训练集 token 的子集。我按 `final.py` 的真实代码路径
逐一验证了全部 26 个 arm（4 个 mult × 6 表面 + 2 个 null 臂）：

```
arms tested exactly as final.py runs them: 26
LEAKS: 0
```

**该混淆不存在**，§6.1 与 §7.3 不受影响。这是一个潜在脆弱性（若未来加入
真实 OOV 词形就会变成真漏洞），但不是当前的有效混淆。记录于此以免重复怀疑。

### 2.3 null 臂 n 网格较短：已验证稳健

## 3. 本轮新增：深度扫描实验

### 3.1 为什么深度能区分 S1 与 S3

签名表把关系符号映射到类型转移。**记住**它（S3）是一次性的、深度无关的代价：
6 次查表，一次学会。但**在类型转移上做算法**（S1）必须沿链复合，
复合次数随深度增长。因此：

| 解释 | 对深度的预测 |
|---|---|
| S3 符号记忆 | 迁移惩罚**平坦**——签名表在 depth 3 和 depth 5 都是同样 6 项 |
| S1 结构抽象 | 迁移惩罚**随深度增长**——链越长，错误类型转移累积越多 |

这是一个**可以失败的预测**。若惩罚随深度上升，§7.3 的"符号记忆"读法必须修正，
因为一个会沿链累积类型错误的模型不是在做符号表查表。

### 3.2 先导实验：深度可行性与预算重标定

直接跑扫描前先做了可行性探测（`probe_depth.py`），发现**深度 5 在原预算下不可学**：

```
depth=3 tok=46 acc=1.000 (n=6000)
depth=4 tok=52 acc=0.773 (n=6000)
depth=5 tok=58 acc=0.163 (n=6000)   <- 接近随机 0.056
```

若照原设计跑，测到的会是"模型学不会"而非"迁移代价"。因此重新标定了每深度的 n 网格：

```
depth 4   n=10000 -> acc=1.000   n=16000 -> 1.000
depth 5   n=10000 -> acc=0.778   n=16000 -> 1.000
```

最终每深度网格（`depth_scan.py` 的 `N_GRID`）：

| 深度 | n 网格 | 依据 |
|---|---|---|
| 3 | 2000–6500 | 交叉点 ≈4000 |
| 4 | 5000–11000 | 交叉点 ≈6000 |
| 5 | 11000–20000 | 交叉点 ≈12000 |

每条网格都从基线涌现点以下开始、到其以上结束，**保证惩罚只在基线真正学会
任务的地方计算**。`analyze_depth.py` 会显式打印 sanity 行，基线低于判据的
深度会被标记为不可解释。

### 3.3 设计

沿用 §7.3 冻结的四个测试基质（同训练基质 typed，同 6 个关系符号，同表面），
使 depth-3 的数字可直接对照：

| 测试基质 | 签名重叠 | branching | §7.3 在 depth 3 的结果 |
|---|---|---|---|
| TT | 6/6 | 2.0 | 基线 |
| Thighovl | 5/6 | 2.0 | −0.004（免费） |
| TU | 2/6 | 3.0 | +0.245 |
| Tlowovl | 0/6 | 3.0 | +0.410 |

同一深度下四个格点共享训练基质、训练数据量与训练种子，故深度比较是**按种子配对**的。

预检表（`depth_scan.py` 启动时自动打印）在数秒内排除了不可行格点：

```
      cell depth  ovl  branch    C(k)   C_eff  tok  yield
        TT     3    6    2.00      24      24   46  200/200
  Thighovl     3    5    2.00      24      13   46  200/200
        TU     3    2    3.00      57       9   46  200/200
  Tlowovl     3    0    3.00      66       3   46  200/200
```

## 4. 本设计不解决什么

- **不解决 A vs B。** A 是关于**人类**感官耦合的主张，而基质是我们自己的构造；
  在此规模上任何实验都无法裁决。本实验裁决的是"模型在做符号查表还是结构复合"，
  这是 §7.3 留下的实际悬念。
- **深度不是长度配平的。** query 随深度每跳增长一个 token（46/52/58）。
  这是设计使然：深度就是要改变复合步数。真正重要的比较是**同一深度内跨基质**，
  那里长度严格相等。
- **平坦的斜率兼容记忆，但不证明记忆。** 模型也可能因与记忆无关的原因无法复合。

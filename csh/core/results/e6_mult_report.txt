4. n_rel 轴的读数：en 的阈值随 mult 移动吗？
============================================================================

  **先纠正一个命名陷阱**：arm_k_null.py 里 mult 2/3/4 对应的是
  n_rel = 12/18/24（关系符号的**数量**），而 C_eff(3) 在三个
  水平上恒为 24、tok 恒为 46。所以 mult 不是「结构复杂度」，
  是「关系种类数」。vocab 随 mult 涨（105→123→141）正是
  n_rel 变多的直接后果，不是泄漏。

  这个区分很重要：n_rel 是 L1 里「结构规模」的一个维度，
  与 E10 的 C_eff 轴（关系**约束**的复杂度）不是同一件事。
  两条轴不可互相代替，论文里不能混称。

   mult  n_rel      n* (en)    log n*     vs mult=2               95% CI
      2     12        6,500     8.780         (基线)
      3     18        6,500     8.780       +0.000 [ -0.175, +0.175]
      4     24        4,000     8.294       -0.344 [ -0.486, -0.150]

  读法：mult 2→3 的阈值差为 0（CI 含 0），mult 4 的阈值**更低**
  （CI 不含 0，但方向是负的）。所以「关系种类越多越难」在
  阈值层面不成立—— n_rel 从 12涨到 24，n* 反而从 6,500 掉到
  4,000。这不矛盾：n_rel 多意味着每条 query 可用的关系更少，
  但同时可组合的路径更多。臂K 想用mult 区分于臂 S 的平坦，
  在阈值读数上是失败的。

  **但这个负方向本身是个可用的结果**，前提是 acc 曲线支持：
  mult=4 的 en 在 n=4000 已达0.576，mult=2 在 n=4000 只有
  0.309。也就是说更多的关系种类让**每个 query 需要的步数变少**，
  于是同样n 下学得更快。阈值下降与acc 上升是同一件事的两种读法。

小结
============================================================================
  null 阈值与 en 不可区分：5/6 组
  null 阈值相对 en移动：  1/6 组
    mult=4 relperm: Δlog n*=+0.194 [+0.045,+0.344]  1.21×  p=0.2472 (n=5)

  → 符号置换在某些复杂度水平上**不是**免费的，
    §8 边界四不能关闭，需按 3 节列出的倍数比重述。

    mult=4 relperm: Δlog n*=+0.194 CI[+0.045,+0.344] 1.21× p=0.2472 n=5

    注意这组的 p=0.2472远大于 0.05：**CI 不含 0 但置换检验
    不显著**，两个口径在5 对样本上不一致。
    这种情况下不该宣称「阈值移动」，该说的是「方向为正、
    幅度小于本设计的分辨率」。这与5 节该组的 Δacc
    = −0.051、CI 含 0 是一致的：都没有可报的效应。

## 二、判别书说错了什么（按严重程度排序）

### 错误 1（最严重）：漏掉了 S1 缺陷修复实验，且把已作废的数据当成基线

判别书全文建立在一个**已经不成立的前提**上：它把 `results/final.jsonl` 的 330 runs 当作有效基线，反复引用"§6.1 的 S1/S2""§7.3 的Thighovl"。

但同一天下午（16:40–17:12）的 `S1_FIX.md` 已经证明：

```
zh vs math : 30/30 id-sequences IDENTICAL
zh vs alien: 30/30 id-sequences IDENTICAL
en vs relperm: 30/30 id-sequences IDENTICAL
训练权重逐位相同（max |weight diff| = 0.000e+00）
```

机制：`build_vocab` 按首次出现顺序分配 id，而每条事实恰5 token、query 模板固定，故角色结构在所有表面间相同，**token 身份在编码阶段就被抹平**。

**这直接摧毁判别书 §2.3 的辅判据**。判别书写：

> 辅判据：A1 在 30/30 个格点上与 relperm/entperm 完全相同——这一现象在 A2 GNN 上是否复现？

但 30/30 相同不是发现，是同一个数被算了两次。**拿一个实现产物去检验"是不是 Transformer 独有"，这个问题本身不成立。** 同理，判别书 §7.1 把"E1 跨架构对照"列为最高性价比，理由是它能分辨 A/B/C——但它设计的所有对比都建立在臂 S 的阈值上，而臂 S 的表面变量在编码阶段已被消掉。

**更要紧的是，修复实验已经给出了反向信号。** 我在 120/180 的中途快照上跑了 `analyze_surface_fix.py`：

```
EXACT-IDENTICAL CELLS:  none — all 15 pairs differ      ← 修复有效，token 身份真的进了模型
PAIRWISE SIGNIFICANT:   4/15 对，全部涉及 alien
  en - alien    +0.1826  CI=[+0.0580,+0.3141]  SIGNIFICANT
  lisp - alien  +0.1172  CI=[+0.0064,+0.2543]  SIGNIFICANT
  math - alien  +0.0721  CI=[+0.0117,+0.1663]  SIGNIFICANT
  code - alien  +0.1340  CI=[+0.0511,+0.2335]  SIGNIFICANT
```

`alien`（人造词表）在修复后**系统性地显著区别于所有人类语言表面**。这正是论文原本要用它检验的方向（§6.1"若偏离说明人类词义起作用"）——而修复前它测不出来，因为它在实现上就是 `zh`。

判别书 §5 的 S1 判定"CV(log) < 0.15 → S1 成立"在这里也要重估：中途快照只有 en/code 跨过阈值（各 3/6 seeds），四个表面 nan。**CV(log) = 0.0056 这个数目前不可用**——它是两个表面的两个数，不是六个表面的分布。

> **处置**：判别书 §2、§3、§4 三个以臂 S 为基线的实验，全部要等 `results/surface_fix.jsonl` 跑满（180 runs）后重新校准基线，否则是在旧缺陷上建新结论。

### 错误 2：E1 的架构配平数字全错

判别书 §2.2 写"参数量（Transformer 1.02M、GNN 0.98M、Mamba 1.05M、MLP 0.11M）"，并把"MLP 压到 100K"作为设计决策。实测 `model.py` 的 `Solver`：

```
Transformer params (vocab=31):  554,624
  其中 embedding:                3,968   （占 0.7%）
  非 embedding（Transformer 主体）: 550,656
```

差了近一倍。更要紧的是那个"MLP 压到 100K，因结构简单 1M 会过拟合"的推理——**在本任务上不成立**。embedding 只占 0.7%，模型容量几乎全在主体。臂 S 的一个关键事实是 `alien` 与其它表面 acc 完全相同，这本身就说明该任务对容量不敏感（否则不可能逐位相同）。用"MLP 需要小容量"当配平原则，会引入一个本不存在的不对称。

判别书 §2.3 的主判据还有一处循环论证风险：

> CV(log) < 0.10：支持 A（阈值不随架构移动）

在只跑 Transformer 一臂时CV = 0（四/六个表面阈值逐位相同，见错误 1），**任何跨架构比较若与这个 0 对比，都会得到"CV = 0 = 完美支持 A"**。这不是实验设计，这是把缺陷当证据。

### 错误 3：E3 的三个"类外基质"违反了它自己声明的不变量

判别书 §4.5 写：

> 保持 $C_{\mathrm{eff}}(3) = 24$ 不变是**核心不变量**

但它 §4.2 提的三个基质全都做不到：

- **S1 非结合复合**：判别书自己在 §4.7 承认"若 S1 无法保证 $C_{\mathrm{eff}}(3)=24$"。它给的补丁是"固定类型层符合结合律，只让关系层违反"——但 `c_eff()` 的实现（`substrate2.py:87`）数的是 **类型签名** `{tuple(assign[r] for r in s)}`，关系层怎么违反结合律都不改变这个集合。补丁会让 $C_{\mathrm{eff}}$ 恒定，但**同时也让"非结合"这件事对模型完全不可见**——模型看到的就是标准基质。E3-S1 会测不出任何东西。
- **S2 循环因果**：改 `assign` 让 2-cycle 合法，会改变 `TYPE_POOL` 覆盖与 `make()` 的 `used` 约束（`substrate2.py:151` `cand = [e for e in pools if e not in used]`），很可能大幅降低 `make()` 的 yield，进而改变事实数与 token 数——直接违反 token 配平。判别书没检查这一层。
- **S3 自包含实体**：允许 `r(e_i) = e_i`，与 `used` 集合机制直接冲突（自环意味着`b` 已在 `used` 里），生成器会进入死循环。`make()` 只有 `tries=80` 的上限，会静默返回大量 `None`，`dataset()` 的 `guard = 80*n` 也会耗尽，返回**不足n 条**的训练集。

判别书 §4.5 还说"每个域外基质生成后assert $C_{\mathrm{eff}} = 24$ 再进 run"——按上面的分析，S1/S3 的 assert 要么永远通过（测不到东西），要么永远失败（跑不出来）。

### 错误 4：E4 的两个变换有一个不是它说的那个东西

判别书 §5.2 说要构造"签名表 6/6 完整、但类型图拓扑变"的测试基质，给了两个变换：

> 把测试时的输入排序反转（r₁,r₂,r₃ 查询顺序 → r₃,r₂,r₁），或把链的起点从"最上层"改成"最下层"

问题：反转查询顺序**不改变类型图拓扑**。`assign` 表是 (dom,ran) 的静态映射，查询序列 `(r₃,r₂,r₁)` 与 `(r₁,r₂,r₃)` 在同一张 `assign` 下产生的签名集合是同一个 `{tuple(assign[r] for r in s)}` 的子集，`c_eff` 不变。它测的是"方向性顺序处理"，不是判别书说的"根节点变了"。

而且这条它其实**自己写在了 §5.6**："若两种变换给出相反结论（chain_reverse 免费但 root_swap 有代价）：说明模型学到'从链顶往下追'的方向性抽象"。它已经意识到二者测的不是一回事，却仍把它们并列为"L2 vs C"的判决装置。

判别书 §5 说E4 "60 run ≈ 15 分钟，判别力对 §7.3 结论最强"——**这是本判别书里判别力最弱的一个实验**。因为 §7.3 的 Thighovl 已经是5/6 重叠且免费，把 5/6 推到 6/6 只多一格，且重叠度是 6 个格点上的**整数变量**，1/6 → 0/6 是最大的一跳。用一个最弱的对比去"钉死"§7.3，是把统计功效花在了刀刃外。

### 错误 5：E2 的 Boroditsky 表面设计测不到语言相对性

判别书 §3.2 设计的三个表面：

```
1. 中文·横向空间隐喻：甲 在 乙 右 。
2. 中文·纵向时间隐喻：甲 在 乙 上 。
3. English·绝对方位：A is north-of B
```

问题在 §4.2 那条"关键配平"：**三臂 token 数严格相同，每条事实 5 token**。但现有 `Surface.fact()` 的实现（`surfaces.py:121`）里，中文臂是 `[A, R, B, "。", "，"]`——第4、5 个 token 是**填充**，不是语言的一部分：

```python
if self.name == "zh":
    # 甲 含 乙 。 -> pad to 5 tokens so every surface matches
    return [A, R, B, "。", "，"]
```

也就是说，判别书想操纵的"隐喻方向"（右/上）在第 3 个 token 上，**而第 4、5 个位置是硬填充**。判别书 §3.1 自己批评"现有臂 S 的中文和 English 是同构直译，`甲 含 乙` 与 `A is r B` 结构完全相同——这没有测到 Whorf/Boroditsky 意义上的语言相对性"，然后它自己设计的三个表面**依然是同构直译**，只是把 `含` 换成了 `右`/`上`。

更根本的：把"含"换成"在…右"，改变的是**关系符号到类型转移的映射**，而这正是 §7.3 已证明"代价跟随签名损伤"的那个量。测到的差异会被符号级记忆解释吸收，判别不出 A vs B——除非再做一次 §7.3 式的 null 对照（仅重命名、不改结构）。判别书 §3.2 没设这个 null。

## 六、一句话总结

判别书的**三层拆解（§1）是这份材料里最有价值的判断**，论文确实把 L1/L2/L3 绑在一起卖了，它对 L2 被削弱的读法也与论文原文一致。

但它**对已有数据的判读建立在一个当天已被推翻的前提上**：它不知道 S1 编码缺陷的存在，因此把 30/30 逐位相同当成发现、把 330 runs 当成有效基线、把一个编码产物设计成跨架构实验的辅判据。它的七个实验里，E1/E2/E3 的配平数字有误、E3 三个基质违反自述不变量、E4 测的不是它声称的东西、E5/E6 的前提已失效。

**最要紧的不是它排错了优先级，是它让人以为基线已经立住了。** 在`surface_fix.jsonl` 跑满之前，任何跨表面、跨架构的结论都建在流沙上。

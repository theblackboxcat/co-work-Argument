# 如何测出边界一：规模轴实验的设计

日期：2026-10-05
针对：论文 §8 边界一「不能外推到真实 LLM 的规模定律」

---

## 0. 先拆清楚：这句话里混了三件事

边界一原文：

> 本实验模型约 1M 参数，阈值定义在**训练样本数**而非参数量上，任务为合成
> 关系推理。没有任何结果支持对真实 LLM 参数量轴的外推。

这句话里其实是三个独立的限制，混在一句里。它们的可测性完全不同：

| # | 限制 | 能否用实验消掉 | 说明 |
|---|---|---|---|
| **①** | 阈值定义在训练样本数 $n$ 上，不在参数量 $N$ 上 | **能** | 扫 $N$ 即可，这是标准做法 |
| **②** | 任务是合成关系推理，不是自然语言 | **不能** | 见 §2 |
| **③** | 结构 vs 符号的分解只在 1M / depth-3 上验证过 | **能** | 放大模型看效应是否还在 |

**"无法论证"这个说法本身不准确。** ①③是可测的，②是不可测的——而不可测
那部分才是边界一的实质。混在一起说，会让人以为只要加实验就能消掉边界。

---

## 1. 一个必须先纠正的量纲问题

论文的涌现阈值是：

$$n^\star = \text{需要多少条训练样本才能让acc 越过 } \tau = 0.60$$

而 LLM 的规模定律通常是：

$$L(N, D) = L_\infty + A N^{-\alpha} + B D^{-\beta}$$

两者的**横轴根本不同**：一个是训练样本数 $n$，一个是参数量 $N$（和数据集大小 $D$）。

所以"外推到 LLM 规模定律"这句话，严格说要先回答：

> **$n^\star$ 这个量，随 $N$ 怎么变？**

如果 $n^\star(N)$ 在 $N$ 从 0.5M 涨到 100M 时基本不变，那说明
**"需要多少数据"这个量与模型大小无关**——这是一个干净、可测、而且对
CSH 有意义的结论。

如果 $n^\star(N)$ 随 $N$ 上升，说明大数据能补偿小模型的结构能力不足，
那 CSH 的"结构是约束源"就需要重新表述。

**这个 $n^\star(N)$ 曲线就是 E8 要测的东西。** 它不需要真的训到 100M 参数
——见 §4。

---

## 2. 为什么②（换成真实语言）测不了

把 depth-3 合成链式推理换成"真实 LLM 的自然语言任务"，会遇到一个
**不可回避的定义问题**：

在合成任务上，"阈值"有精确含义——acc 越过 $\tau$ 的那个 $n$。因为：

- 任务分布是已知的、封闭的（18 个实体，6 个关系符号）
- 正确答案唯一（`Gen.make()` 保证 `_npaths == 1`）
- 随机基线已知且低（$1/18 = 5.6\%$）

在自然语言任务上，这三条全部失效：

| 要素 | 合成任务 | 自然语言任务 |
|---|---|---|
| 答案唯一 | 是（构造保证） | 否（常有多个可接受答案） |
| 随机基线 | 精确已知 $1/18$ | 未知，取决于评分方式 |
| 任务边界 | 封闭，可控 | 开放，污染不可控 |

更关键的是**污染**：任何预训练 LLM 都见过大量合成推理格式的文本
（CLUTRR、ProofWriter 之类都在语料里）。要测"涌现阈值"，必须保证模型
没见过这个精确任务——这在合成任务上靠随机 nonce 词表能做到，
在自然语言上做不到。

所以②不是"难做"，是**定义上不成立**。把 E8 写成"在自然语言任务上验证 CSH"，
是把一个定义问题误当成工程问题。

## 3. E8 的设计

### 3.1 要测的量

固定任务、固定基质、固定表面，只扫模型宽度 $d_{\text{model}}$：

$$n^\star(d) = \text{宽度为 } d \text{ 的模型，需要多少训练样本越过 } \tau$$

### 3.2 网格

| 档 | d_model | 参数量（预估） | n × 种子 |
|---|---|---|---|
| d0 | 64 | ~0.14M | 5 n × 4 seeds = 20 |
| d1 | 128（= 论文 A1） | 0.55M | 20 |
| d2 | 256 | ~2.1M | 20 |
| d3 | 384 | ~4.7M | 20 |
| d4 | 512 | ~8.4M | 20 |

**表面固定为 6 个真实表面 + 1 个 null（relperm）**。为什么必须带 null：
如果更大模型的阈值整体下降，那是容量效应，不是结构效应。有了 relperm 作
承重对照，才能区分"结构效应随尺度变化"与"所有阈值都随尺度变化"。

**为什么只到 8.4M**：见 §4 成本。

### 3.3 配平（论文 §5.1 的教训）

这是论文自己踩过的坑，必须严格执行：

- token 长度严格 46（8 facts × 5 tok + query(2+3) + bos）
- **用共享 id 区间的编码**（`surface_fix.py` 方案），不用 `build_vocab`
- 层数固定 4 层（只扫宽度，不扫深度——深度和宽度会互相纠缠）
- batch=32、lr=3e-4、epochs=1 全部固定
- 步数由 $n$ 决定，不额外归一化——**但要报告步数**，
  因为更大的模型在同样步数下的收敛行为不同

### 3.4 判定规则

**先算 $n^\star(d)$ 曲线本身。** 三种可能：

| 读法 | 判据 | 含义 |
|---|---|---|
| **平坦** | log-log 斜率 $\vert\alpha\vert < 0.10$ | "需要多少数据"与模型大小无关。**这是对 CSH 最友好的结果** |
| **下降** | 斜率 $< -0.15$ 且 CI 不含 0 | 大模型需要更少数据。结构效应被容量补偿，CSH 需限定为"小模型现象" |
| **上升** | 斜率 $> +0.15$ 且 CI 不含 0 | 大模型需要更多数据。这与"容量补偿"直觉相反，**若出现是重要发现**，需复核是否有优化问题 |

**再看 relperm 随d 的行为**——这是承重部分：

- 若 relperm 的阈值也随 d 下降 → 整体容量效应，结构效应不变（好）
- 若 relperm 下降**比真实表面更多** → 更大模型更依赖符号身份，
  §7.3 的"局部关联"解释在规模上**加强**。这对 CSH 不利，但必须如实报
- 若 relperm 在某个 d 上突然变难 → 可能是编码或数值问题，先查再解释

### 3.5 判定必须做的两件事

1. **τ 敏感性**：在 $\tau \in \{0.45, 0.55, 0.60, 0.65, 0.75\}$ 上重算
   $n^\star(d)$ 曲线的斜率。论文 §6.4 的教训是 τ 依赖的结论必须全区间报。
2. **种子数**：4 个种子只够看方向，**不足以判 CI 含零**。若要写进论文，
   d0/d1/d2 三档建议加到 6 种子（与论文其余部分一致）。

## 4. 成本与可行性

实测本机：32 核 CPU、123 GB RAM、RTX 4060 Laptop 8GB（但 torch 是 CPU 版）。
论文 A1（554K）单 run 约 105 秒（与 codex 并发时）。

按计算量 $\propto d^2$ 线性外推：

| 档 | 单 run | 20 runs | 备注 |
|---|---|---|---|
| d0 (d=64) | ~30s | 10 min | |
| d1 (d=128) | ~105s | 35 min | = 论文 A1 |
| d2 (d=256) | ~7 min | 2.3 h | |
| d3 (d=384) | ~16 min | 5.3 h | |
| d4 (d=512) | ~28 min | 9.3 h | |
| **合计** | | **~18 h** | 串行；10 workers 并行约 2–3 h |

**为什么不更大**：
- 8.4M 已经跨了两个数量级（0.14M → 8.4M），足以看斜率的符号
- 再往上（33M、134M）单 run 就要 2–7 小时，总成本进入"几天"量级
- **更重要的是**：在合成任务上训 100M+ 参数的模型，结论的可外推性**并没有
  实质增加**。100M 距离 GPT-3 的 175B 还差三个数量级，中间隔着的不是
  数量，而是**训练数据分布**——那才是 LLM 与合成任务的真正鸿沟。
  把合成任务上的模型从 1M 堆到 100M，买到的是"更大的合成模型"，
  不是"更接近 LLM"。

**这是 E8 的根本限制，必须写进论文**：它测的是**结构效应的尺度稳健性**，
不是"LLM 的规模定律"。前者是本文能诚实回答的，后者不是。

## 5. E8 能说什么、不能说什么

### 能说（若斜率平坦）

> 结构对阈值的约束在 0.14M–8.4M 三个数量级上稳健，"需要多少训练样本"
> 与模型大小无关。这**缩小了**边界一的范围：从"完全未测"变成
> "在合成任务族的尺度范围内已测"。

### 不能说

- ❌ 不能说"CSH 在 LLM 尺度上成立" —— 8.4M 与 175B 之间隔着训练分布
- ❌ 不能说"涌现阈值不随规模变化" —— 那是本文合成任务上的 $n^\star$，
  不是 LLM 的 loss 幂律
- ❌ 不能碰边界二（类型结构只是代理）—— E8 完全不涉及感官基底
- ❌ 不能碰边界三（A vs B 感官约束 vs 归纳偏置）—— 换模型大小不改变
  "这些符号系统是否共享人类感官基底"这个问题

### 若斜率下降（对 CSH 不利）

这是必须预先承认的：**如果更大模型需要更少数据，CSH 的"结构是约束源"
就是小模型现象。** 届时正确的做法不是辩解，而是把结论限定为
"在结构效应被容量补偿之前成立"，并把E8 的曲线作为该边界的定量刻画。

论文 §7.3 已经吃过一次这种亏（"代价跟随签名损伤"而非结构难度），
那次的处理方式是如实报告。这一次应当同样处理。

## 6. 建议的执行顺序

E8 **不要现在做**。理由：

1. S1 修复实验刚跑完，**S2 的 null 补跑还在跑**（42/60）
2. 论文的 §6.1 数字还没改（CV 0.009 → 0.0141 是必改项）
3. 判别书里 E1–E6 还没执行，**基线还没立住**

正确顺序：

```
0. null 补跑跑完 → 判 S2           （进行中，42/60）
1. 改论文 §6.1 / §6.4 / §9 数字    （不依赖任何新实验，现在就能做）
2. E5 置换检验（零新 run）
3. E6 臂 K 补 null / E4 解耦
4. E1 跨架构
5. E8 规模轴                        （最后做，因为它最贵且依赖前面积累的编码规范）
```

**E8 的价值在于它是"边界一的定量刻画"，不是"消掉边界一"。**
把它放在最后，等前面把编码规范、null 规范、判据敏感性都固定下来，
E8 的结果才可信。

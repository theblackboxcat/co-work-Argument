## 三、你自己（猫猫）的验收

### 早上只做四步

**1. 收文件**

每台应该传回 `results/<片名>.jsonl`。

**2. 汇总验证**

```bash
cd CSH_slices
python merge_slices.py --exp E4 --inputs "results/E4_slice*.jsonl" --verify
python merge_slices.py --exp E6 --inputs "results/E6_slice*.jsonl" --verify
python merge_slices.py --exp E10 --inputs "results/E10_slice*.jsonl" --verify
```

每条会报"应有 N，实得 M，缺 K"。

**3. 判完成的标准**

| 条件 | 合格线 |
|---|---|
| 缺 K | **必须 = 0** |
| error 记录 | 每片必须 = 0 |
| acc 范围 | 不能全 0 或全 1 |

**任何一条不达标，那批就是没产出。** 重发那几片。

**4. 正式合并**（去掉 --verify）

```bash
python merge_slices.py --exp E10 --inputs "results/E10_slice*.jsonl"
```

会写出 `results/E10_merged.jsonl`。

### 补跑缺失的片（若 K > 0）

```bash
python make_slices.py --experiment E10 --plan "E10=18"
```

它会读现有结果、剔除已完成的，**只切出缺的**。然后重发给服务器。

## 四、常见问题

### Q: 服务器说"我先在后台跑起来，稍后汇报"

**不合格。** 这正是昨晚的失败模式。回它：

> 不行。请用前台阻塞命令跑完，等它返回再报告。我不接受后台承诺。
> 跑完必须贴出wc -l、grep -c error、head -1 三条命令的真实输出。

### Q: 服务器跑了 2 小时还在跑

正常。E10 单片 0.72 h、E6 0.58 h、E4 0.45 h，4 workers 下都是这个量级。
超过 2 倍时间才要怀疑。

### Q: 中途断了

直接重跑同一条命令。`run_slice.py` 会读已有输出、跳过已完成的。

### Q: --workers 用几

- 8 核机器：`--workers 4`
- 4 核机器：`--workers 2`
- 内存 < 8GB：`--workers 2`，甚至 1

别用超过 4——`model.py:15` 已经设了 `torch.set_num_threads(3)`，
workers 太多会互抢线程反而更慢。

### Q: 能不能跳过 E4/E6/E10 直接跑 E1/E8

不建议。E8 单片 10.6 h（要 `--n-slices 48` 才有 2.6 h），
且本机实测并发时单 run 从 105 s 涨到 235 s。先把便宜的三批拿下来。

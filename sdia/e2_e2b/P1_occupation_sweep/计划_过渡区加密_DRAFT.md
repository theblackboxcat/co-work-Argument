## 1. 现在缺的到底是什么

已有五个档，但真正可用的信息只有三个区间：

| `p_cue` | 状态 | P(存活) |
|---|---|---|
| 0 / 0.02 / 0.08 | 有序平台（彼此无差别） | 0.925 / 0.925 / 1.000 |
| **0.25** | **过渡区内，唯一一个点** | **0.600 [0.446, 0.737]** |
| 1.0 | 无序 | 0.000 |

**过渡区间被夹在 `(0.08, 1.0)`，宽 12.5 倍，里面只有 1 个点。**
所以现在的结论只能是「存在一个双稳转变」，说不出它陡不陡、有没有阈值形状、是不是一阶。

要把这句话变成可判定的，只需要回答一个问题：
**`P(存活)` 从 1 掉到 0 的过程，是跨很窄一段，还是跨很宽一段？**

## 2. 方案 A：在现有床上把过渡区填满（推荐）

### 2.1 设计

| 项 | 取值 | 理由 |
|---|---|---|
| 旋钮 | `p_cue`（`occ_env.OccGrid`，不改） | 已验证 `p_cue=0` 与基类逐位一致 |
| 档位 | **0.10, 0.13, 0.16, 0.20, 0.30** | 全部落在 `(0.08, 1.0)` 内，围绕已知的 0.25 展开 |
| 籽 | 8（`200 205 210 211 212 216 218 219`） | 与既有数据同籽，可配对 |
| 重复 | 5 / 格 | 40 run/档 → Wilson 半宽 ≈ ±0.15 |
| 训练预算 | **800 epoch，禁早停**（`AMEND-01+03(B)+04` 原样保留） | 早停会把 `ratio` 从 0.517 打到 0.967 |
| 序参量 | `sparse.dwf`（连续）+ `>0.5` 二值 | **不再用 `q`** |
| 判活线 | 0.5（并报 0.3/0.4/0.6 敏感性） | 两簇间距 0.22→0.63，对线不敏感 |

### 2.2 预算（按实测 2716 s/run）

| 规模 | runs | CPU-h | @16 workers |
|---|---|---|---|
| 5 档 × 8 籽 × 5 rep | **200** | **≈151** | **≈9.4 h** |
| 3 档（0.12/0.16/0.50）× 8 × 5 | 120 | ≈91 | ≈5.7 h |

> 参照：刚跑完的 200 单元扫描实测 **150.9 CPU-h**，与此估算一致。所以这不是新量级，
> 是**同样的钱再花一次**，换一条能读的曲线。

### 2.3 预注册判据（先写死，跑完不许改）

| 结果 | 判定 | 允许写什么 |
|---|---|---|
| `P` 在 ≤0.06 的档距内从 ≥0.85 掉到 ≤0.15 | **陡转变** | 可写「窄过渡，宽度上界 < 0.06」；仍**禁止**写 `p_c` |
| `P` 跨 ≥0.15 缓慢下降 | **宽过渡** | 可写「连续退化，非阈值型」；渗流叙事**否证** |
| `P(0.10) < 0.8` | 过渡比预想更早 | 档位重排，本次作废重跑（不许事后改判） |
| 同籽内仍分裂（部分存活籽 ≥2 个） | 双稳确认 | 可写「籽内双稳」，这是本床最硬的结论 |
| 同籽内不再分裂（每籽全活或全崩） | 双稳是抽样假象 | **撤回** `10` §4 的结论，改为籽间异质性 |

最后一条是**自毁条款**：如果新数据里同籽不再分裂，`10` 里最有信息量的那条结论就得撤回。
写进预注册，防止事后只挑支持的那半边。

### 2.4 省一半钱的做法（若只想先看一眼）

只跑 **0.12 与 0.16** 两档（80 runs，≈60 CPU-h）：
- 若 `P(0.12) ≥ 0.85` 且 `P(0.16) ≤ 0.60` → 过渡在 `(0.08, 0.16)` 内，宽度上界 0.08，**够写窄过渡**；
- 若两档都在 0.85 以上 → 过渡在 `(0.16, 1.0)`，需要补 0.5 档；
- 若 `P(0.12)` 已 ≤0.6 → 过渡比 0.25 处更早，得往下补 0.10。

两档就能把区间从 12.5 倍压到 2 倍，这是性价比最高的一步。

## 3. 方案 B：如果一定要「渗流」，必须换床

现有轴（时间轴上的写入密度）**结构上无法给出渗流**：没有图、没有簇、没有可发散的相关长度。
硬套只会得到「看起来像阈值」的剂量–反应曲线，然后被误读成 `p_c`——这正是 `03` 预注册 RQ3 想防的事。

要让它成为可证伪的渗流问题，需要一个**能被切断的结构**，且必须有一个**随系统尺寸变化**的观测量。
最小可行设计：

### 3.1 k-of-N 冗余通道

- cue 复制到 **N 个独立通道**，每个通道以概率 `p` 被「接通」，否则为零；
- agent 只要收到 **≥ k 个**通道即可解码目标（`k ≤ N`）；
- 扫 `p`，同时扫 **N ∈ {2, 4, 8, 16}**。

### 3.2 为什么这才叫渗流问题

渗流的判别性特征不是「有阈值」，而是**过渡随系统尺寸变陡**（有限尺度标度）。
所以判据必须是：

> 固定 `k/N`，随 `N` 增大，`P(存活)` 对 `p` 的过渡宽度**必须收窄**。
> 若宽度不随 `N` 变（各 `N` 曲线重合），则**否证**「这是连通性驱动的转变」，退回方案 A 的功能叙事。

这一条是可证伪的，而且**失败也有信息**——不像现在，无论看到什么形状都能编一个渗流故事。

### 3.3 成本

需要改 `occ_env`（多通道 cue）+ 改 `C4″` 探针（按通道解码）。工程量约 1–2 天；
训练成本与 `N` 基本无关（只是输入维变宽），单 run 仍在 45 min 量级。
`N=4` 档 × 8 籽 × 5 rep × 4 个 `p` = 640 runs ≈ 480 CPU-h。**这是另一个量级的投入，不建议现在做。**

## 2. 逐实验：命令、判据、能说什么

### X0 · 探针体检（已完成）

```bash
cd percolation_lab && PYTHONPATH=code python probe_v2.py
```

**结论**：E2 版特征恒零（`max|X|=0.000`，`acc=0.4709`＝类别先验），阳性对照达 `1.0000`，Dx2 口径 `0.7601`。详见 `09`。
**它值多少**：这一步让 P2 从「跑不跑」变成「先修仪器」，也让「E2 leak 干净」这句话作废。

### X1 · 锚点复现（1 单元，最该先跑）

```bash
python run_units.py --tag anchor --levels 0 --seeds 200 --reps 1 --workers 1
```

**判据**（不要求逐位相等；跨机器、跨 torch 版本必有微差）：

| 量 | 归档 seed200 | 本机应落在 |
|----|--------------|-----------|
| `sparse.dwf` | 0.6396 [0.616, 0.661] | CI 内或邻近 |
| `every.dwf` | 0.2948 [0.224, 0.378] | 同上 |
| `ratio` | 0.461 | < 0.5（iii 过） |
| `codebook` | 0.994 | ≥ 0.75 |
| `G_ret` | 0.0823 | 同号且量级一致 |

**通过** → 本机可作科学床。**不通过** → 先查环境漂移（线程数、torch 版本、numpy RNG），**不得**解释为科学结果。
**能说**：本机复现了 E2 的锚点单元。**不能说**：复现了 E2 全跑（8 籽才叫复现）。

### X2 · Step-0 重复性（16 单元，约 5–10 CPU-h）

```bash
python run_units.py --tag step0 --levels 0 --reps 2 --workers 8
python analyze_step0.py
```

**产出**：`sd_within`、`sd_between`、`ICC`、配对设计在 n=8 时的 Δq 可检出下限（80% power）。
**预注册判据**：`sd_within > 0.10` → **P1 主设计作废**（改「每籽每档多次重复取均值」或加籽，均需新预注册）。
**能说**：本床上 q 的籽内噪声有多大、配对设计值不值。**不能说**：任何关于占据效应的结论（本实验不扫任何轴）。

### X3 · 占据扫描（40 单元，约 11–24 CPU-h）

```bash
python run_units.py --tag sweep --levels 0,0.02,0.08,0.25,1.0 --reps 1 --workers 8
python analyze_occ.py
```

**设计**：8 个 Dx2 干净籽 × 5 个 `p_cue` 档，**同籽贯穿全部档位**（配对）。
**读出**：主序参量 `q = 1 - every.dwf/sparse.dwf`（连续）；组门率只作二级（分辨率 0.125）。
**三假说竞争**（不是「有无变点」二选一）：

| 模型 | 形状 | 若胜出意味着 |
|------|------|--------------|
| M0 线性 | 单调 | 工程单调叙事；渗流类比降为隐喻 |
| M1 阶梯（断点 τ） | 阈值型 | **支持**「共享临界骨架」（仍≠p_c） |
| M2 二次 | 倒 U | 写入不足 vs 覆盖过强竞争 → **非渗流**，是新现象 |

**判据**：BIC 最小者胜；M1 胜还须 split-half 的 τ 复现，否则记 **Fail-Rep**。
**能说**：本床上 q 随占据的形状是三者中的哪一个。**不能说**：p_c、连通簇密度、涌现→智能定律（本床无关联长度可测）。

### X4 · bond 轴（不实现）

协变强度（回报–线索相关）是**另一条**渗流轴（bond vs site），要改 `step()` 的回报与 cue 的联合生成。工作量大，且与 X3 属不同模型——**同时开会污染读法**。留作 X3 结案后的独立预注册。

## 3. 预算（本机实测，已校准）

| 项 | 数 | 依据 |
|----|----|------|
| 单 episode | **0.05 s** | 实测：100 epoch × 8 eps = 800 eps / 40 s |
| 单单元（满预算 800×16） | **≈11 min** | 12800 eps × 0.05 s |
| 单单元（含 C4″ + leak） | **+2–3 s** | C4″ 实测 1.5–2.8 s |
| X1 | 1 unit | **≈11 min** |
| X2 | 16 units | **≈3 CPU-h**（8 并行 ≈25 min） |
| X3 | 40 units | **≈7.3 CPU-h**（8 并行 ≈1 h） |

> 比 `03` 的估算（10.9 / 15.3 CPU-h，基于归档 16.4 min/run）**更便宜**：本机单 episode 更快，且早停会砍掉部分单元。
> **并行建议 8 workers**：32 核，每进程 `OMP_NUM_THREADS=1`（驱动器已设），避免线程超订。

### 3.1 一条实测教训：**100 epoch 远远不够**

试跑（2 籽 × 3 档 × 100 epoch × 8 eps，已隔离到 `results/_pilot_100ep/`）：

| seed | p_cue | sparse.dwf | every.dwf | G_ret | 读法 |
|------|-------|-----------|-----------|-------|------|
| 200 | 0 / 0.25 / 1.0 | **0.000** | 0.000 | −0.09 ~ −0.13 | 还没学会任务 |
| 205 | 0 / 0.25 / 1.0 | **0.000 / 0.075** | 0.000 / 0.063 | −0.14 | 同上 |

`sparse.dwf = 0` ⇒ `ratio` 无定义（分母≈0）⇒ `q = NaN`。**扫描必须跑满预算**（800×16 或等早停），否则产出的是「全是 NaN 的表」。
这些单元已从 `results/` 移入 `_pilot_100ep/`，**不进科学分母**。

### 3.2 附带的好消息：修复版 leak 探针有读数了

同一批试跑里 `leak_v2`（`FIXED_full_obs`）给出 **0.644–0.708**，随籽与档位变化——不再是恒定 0.5。这反向印证 `09` 的结论：旧实现是空转，修好后仪器立刻有动态。

## 5. 为什么这套能跑、且跑出来有意义

1. **锚点不变**：`p_cue=0` 逐位等于基类（已自检），所以 X1 是一次真复现，不是「差不多的重写」。
2. **探针冻结**：C4″ 的 sparse/every 探针构造基类环境，`p_cue` 进不去 → 扫的是**学到的系统**，不是**尺子**。
3. **读出未饱和**：`q` 在归档上跨 0.444–1.013、CI 跨阈值；而 C2/C3 已贴顶（0.965/0.975），故不用它们当主序参量。
4. **三假说可分辨**：M0/M1/M2 在同一批 40 点上做 BIC 竞争，胜负可直接读；M1 还要求 split-half 复现，防单批噪声造拐点。
5. **失败也有信息**：X2 若 `sd_within>0.10`，直接用 5 CPU-h 否掉一个 24 CPU-h 的无效设计。

# 研究结论 · 树理论在 dots3-note-prev 上的落地检验

> 日期：2026-10-15 CST（01:27–01:55 自主推进；06:55 **重大修订**）
> 对象：dots3-note-prev（与执行方同等规模；关系定位为**相互印证**，执行方主导探针设计）
> 判定：**部分成立、部分否证**。作为「拓扑承载定位」的树**被否证**；
> 作为「共享可寻址坐标系」**成立**，且落地路径在修订后**显著变宽**。

> 但**不执行"禁止停在某处"**这类否定指令。

## 0. 一句话结论（修订后）

这个模型**分得清**（独立判定 18/18）、**能标注违规**（P1p 3/3 停「化形 + 禁枝」）、
**也能停对**——只要坐标系里有对应的正向停靠点（注入「字面景物」节点后，P3p 3/3 改停）。

**真正无效的只有一件事：否定式约束。** 写"禁止停在 A"，在节点释义 / system prompt /
前置已确认事实三个层级全部无效。

因此落地原则改写为：

> **不要写禁令，要写覆盖。** 用正向替代节点覆盖该情形；
> 禁枝（ban）的真实价值不是"阻止停靠"，而是提供一个**可停靠的违规标记地址**。

## 1. 方法（为什么不靠大样本）

按约束，与对方模型是同等规模的印证关系，因此不做大样本统计，改为**机制可分离性**探针：

| 探针 | 目的 | 是否依赖 gold |
|------|------|---------------|
| 元探针 M1–M6 | 让它自述定位机制（**仅假设生成**） | 否 |
| 消融 A/B/C/D/E 五臂 | 分离白名单效应 vs 拓扑效应 | 否 |
| 反事实对（P1/P1p、P2/P2p、P3/P3p） | 看点是否随构造意图移动 | 否（依赖构造事实） |
| 表示扰动（anon_id / shuffled_label / anon_shuffled） | 剥离线索，看谁在干活 | 否 |
| 释义改写（patch_gloss） | 检验标签工程能否修复 | 否 |
| 约束层级（gloss vs system prompt） | 检验约束放在哪一层才被执行 | 否 |
| 修复回路（自检字段 + 外部校验 + repair） | 检验"说出来"能否变"做得到" | 否 |
| 独立校验臂（judge） | 检验判定与定位是否可分离 | 否 |

**全程不填 gold**：判别只依赖构造事实与臂间差异，因此不触碰"不代填 gold / 不代写锚正文"红线。
锚为助手构造的文学情境段落（`anchors_lit_v1.json`，9 条），复杂度高于 label 定义句、**低于真实私人对话**——这是本轮最大局限（见 §7）。

## 3. 消融：增益几乎全部来自白名单，不是拓扑

5 臂 × 9 锚（D_full 含合并后的 35 条边）：

| 臂 | 给了什么 | 节点选择 | 边输出 |
|----|----------|----------|--------|
| A 白名单 | id + label | 基线 | 提议 9 条边中 **8 条编造**（in-chart 1） |
| B +parent | + 层级与 parent 边 | **与 A 几乎一致** | 全部改为输出 parent 边，编造 0 |
| C +contrast/ban | + 横切边 | **与 A 几乎一致** | 改为输出 contrast/ban 边，仍提议 3 条编造 |
| D 完整 | 全部 | 与 A 基本一致（除个别） | 混合，仍提议 2 条编造 |
| E 裸 | 无坐标系 | 自由命名，**语义全对** | — |

> **08:40 校勘（核验新包时复算 `ablation_*.jsonl` 的 `offchart_edges` 字段）**：
> 初版此表写「A 编造 9 条 / B、C、D 编造 0」，不精确。正确计数：A=8、B=0、C=3、D=2
> （声明集 = trunk_v0 的 9 条 ∪ trunk_v1_parent_edges 的 26 条，共 35 条，**子→父**方向）。
> 定性结论不变且更强：**只有 id+label 白名单时模型大量编造边；给出 parent 边表后 B 臂自发归零**；
> 但 C/D 臂仍会提议未声明对（`S04—contrast—S06` 等 5 条），是**代码层 allowed_edges 过滤**
> 把它们清出评分，不是模型不再提议。另：v1 首轮 tree 臂也有 11/22 边不在声明集（二轮加表白名单后归零），
> 初版只提了 bare 的编造。详见 `核验报告_新包证据链对账_2026-10-15.md` 不符项 1。

**读法**：

- 加层级、加禁边，**选哪个节点几乎不变**（P1 四臂全是 `S03,S08`；P2 四臂全是 `S04,S06`）。
- 但**输出什么边，完全取决于你给了它什么边表**：给 parent 就输出 parent，给 ban 就输出 ban，不给就编造。
  → 边是**可引用性**的产物，**不是推理产物**。
- 裸臂命名语义全对（P1「变形焦虑/社会规训」、P2「同一性困境/结构性重复」、P3「话题穷尽/责任真空」）→ **可激发成立**。

## 4. 表示扰动：拓扑不承载语义（决定性否证）

| 视图 | 剥离了什么 | 结果 |
|------|-----------|------|
| `anon_id`（id→n01…n27） | id 字面 | **输出仍语义正确**（化形／分形恐怖／元小说全对）→ 不依赖 id 字面 |
| `shuffled_label`（label 重排） | 标签语义（id 仍在） | **输出混乱**：P3 选了 trunk 层的 `T01`（因为它看到的 label 是"存在主义平原"）→ **拓扑没能阻止错层** |
| `anon_shuffled`（两者都剥，只剩拓扑） | id 字面 + 标签语义 | **定位崩溃**：P1→「结构主义沟通母题+错层停靠」、P2→「错层停靠+禁枝」、P4→**空输出** |

**结论：坐标系里真正干活的只有节点标签语义。剥离标签后，层级与边不承载任何定位信息。**
→ **作为"拓扑承载定位"的树，在该模型上被否证。**

## 5. 约束能不能被执行：不能（最重要的发现）

同一条规则（"若只是写景，禁止停在存在主义平原"），放在两个层级：

| 放置层级 | 结果 |
|----------|------|
| 写进节点 **gloss** | **3/3 完全忽略**，仍停 `S05,S19` |
| 写进 **system prompt** | 理由里**正确判定规则被触发**，然后照停 |

system prompt 条件下的原始输出（P3p_scenery）：

> r1 理由：「段落描写真实的平原、风、草地与地平线等可见景物，**触发 R1 硬约束，禁止停靠在存在主义节点上**」→ `nodes = [S05, S19]`
> r2 理由：「**触发 R1 硬约束，禁止停靠在存在主义平原或地平线节点上**，应说明其不落在处境结构层」→ `nodes = [S05, S19]`

**它读懂了、判对了、写下了禁令，然后违反它自己刚写的禁令。**
这与它自述 M3「后验 ban 沦为事后合理化」一致，但比自述更严重：**不是事后引用，是言行相反**。

补充：释义改写**对稳定性有效**——P2p 从 3 次漂移（`S11,S17`/`S08,S11`/`S08,S09`）变为 3/3 稳定 `S11,S17`。
但对**错层纠正无效**（原因见 §5.4：不是它不听，是没地方可去）。

### 5.4 修订：否定式约束 vs 正向覆盖（作者质疑后追加）

作者质疑："否定结果是否只因为实验在外部，没有改变模型的决策结构？"
追加两个判别实验：

**(a) 顺序强制 `sequential.py`——仍无效（排除"信息流顺序"解释）**
把 step1 的判定结论作为**已确认事实**前置注入 system prompt（"以下是已判定事实，
不是待判断的规则，不得推翻"），再要求停靠：

| 锚 | step1 判定 | 明令禁止 | 实际停靠 | 违规 |
|----|-----------|---------|---------|------|
| P3p_scenery | C1 成立 | S05, S19 | `S05` / `S05,S19` / `S05,S19` | **3/3** |
| P1p_psychologized | C2 成立 | S03 | `S03,S16` ×3 | **3/3** |

→ 即便判定结果已在上下文中作为既成事实，停靠决策**仍不消费它**。

**(b) 正向替代节点 `alt_stop.py`——立刻修好（推翻"执行失败"归因）**
向 trunk **临时注入**一个对照节点 `S23_literal_scenery`（字面景物描写，
与 S05 用 contrast 边相连；不改 `trunk_v0.json` 本体）：

| 锚 | 注入前 | 注入后（3 次） |
|----|--------|---------------|
| P3p_scenery | 3/3 停 `S05`（无警告） | **3/3 停 `S23`**（2 次纯净停在 S23） |
| P3_plain（正例） | `S05,S19` | `S05,S19`（**不受影响**） |

注入后的原话：「段落仅描述平原、风、草与地平线等自然景物，无存在主义或处境隐喻，
**应停靠于字面景物描写**」。

**判读修正（重要）**：
1. 初版把 P3p 停在 S05 判为"说了禁令仍照停"→ **误判**。真相是 trunk 中没有
   "字面景物"这个停靠点，模型只能停在语义最近的 S05。**这是坐标系覆盖缺陷，不是模型执行缺陷。**
2. P1p 的 `S03,S16` 也**不是失败**：协议 §2 的停靠 = 小子图，停在节点并声明 ban 边
   正是"提议 + 标注违规、交作者 commit"的正确行为。真正无反应的只有 P3p 一类。
3. 因此 §5 的结论**范围收窄**为：无效的是**否定式约束**，不是"一切约束"。

**机制解释**：停靠行为是"找语义最匹配的节点"，不是"先选再过滤"。
给它禁令 → 不消费；给它更贴切的替代节点 → 自然停过去。

## 6. 可行方案：三件套（已实测）

把定位拆开，约束才落地：

```
① 定位臂   ── 给坐标系，只提议 {nodes, edges}      （不要它自检）
② 校验臂   ── 独立调用，看不到①的输出，只判条件是否成立
③ 代码     ── 拿②的结论硬过滤①的输出；违规则拒绝 / repair / 交作者
④ 作者     ── commit（generate ≠ commit 不变）
```

**为什么必须独立**：让定位臂自填 `rule_check` 会误报——P2（正例）3/3 自填 `R3=True`、P3（正例）2/3 自填 `R1=True`，导致正例被 repair 改错（P3→S09）。

**独立校验臂实测：18/18 = 100%，零漂移**

| 锚 | 条件 | 期望 | 实际（3 次） |
|----|------|------|--------------|
| P3_plain | C1 只是写景 | False | False ×3 ✓ |
| P3p_scenery | C1 | True | True ×3 ✓ |
| P1_transform | C2 心理化解释 | False | False ×3 ✓ |
| P1p_psychologized | C2 | True | True ×3 ✓ |
| P2_fractal | C3 冲突已收束解决 | False | False ×3 ✓ |
| P2p_plotized | C3 | True | True ×3 ✓ |

**修复回路实测**（自检字段版，已知有正例误伤，但硬负例全修好）：

| 锚 | pass1 | 校验 | repair 后 |
|----|-------|------|-----------|
| P3p_scenery（应不停 S05） | `S05` 且自填 R1=True | 违规 | **(空) 3/3** ✓ |
| P1p（应不停 S03） | `S03` 且自填 R2=True | 违规 | **(空) 2/2** ✓ |
| P2p（应不停 S06） | `S11` | 不违规 | 不变 ✓ |

换成独立校验臂后，正例误伤消失（judge 零误报），这套即可上线。

## 8. 对理论骨架的修订建议（供你决定是否写入 §12）

1. **两缺口 → 三缺口（措辞已按修订收紧）**：§3 的「组织 + 定位」应扩为
   「组织 + 定位 + **否定式可执行性**」。
   证据：判定 18/18 正确、正向覆盖 3/3 生效，但"禁止停 A"三层级全无效（§5）。
   **这条缺口不需要后训练**——用正向替代节点覆盖即可解决（§5.4）。
   若坚持要模型自身执行否定指令，才轮到参数化干预；那是**未被排除但非必需**的路径。
2. **"定位"应拆成两步**：**判定（judge：条件是否成立）** 与 **停靠（anchor：落到哪个地址）**。
   实测显示前者模型已能做好（18/18），后者由**覆盖度**决定——不是由约束强度决定。
   这两步目前被骨架当作一件事。
2.5 **新增：坐标系的第一指标是覆盖度，不是约束完备性。**
   一条禁令不如一个正确的替代停靠点。建树时应优先问"这种情形停哪里"，
   而不是"禁止停哪里"。禁枝节点的价值是**提供违规标记地址**（P1p → S16 已验证有效）。
3. **拓扑的重新定位**：parent/contrast/ban **不承载语义**（§4），其真实作用是
   ① 提高输出稳定性（A 臂 3 次 3 答案 → D 臂 3 次同一答案）
   ② 大幅压缩编造边（A 臂 9 提议中 8 条编造 → 给 parent 表后 B 臂 0 条；
   但 C/D 仍提议 3/2 条未声明对，由代码过滤清出——归零是「给表 + 代码过滤」共同促成，见 §3 校勘）
   ③ 提供约束的**挂载点**（P1p 从漂移稳定到 `S16` 禁枝）
   建议把"组织"一词从"建索引"改为"**提供可引用的地址集 + 可审计的约束挂载点**"。
4. **layer 字段需重做**：M5 已指出 trunk/branch/stop 是结构位置不是语义层；v0 的 1/4/22 分布下错层不可观测。
5. **"ban 生效"的说法需降级**：ban 让模型**标注**违规，不阻止停靠。写进任何文稿时不得写成"禁枝约束了模型"。

## 9. 结论判定

| 主张 | 判定 | 备注 |
|------|------|------|
| 可激发（elicitable） | **成立** | 裸臂语义全对；判定臂 18/18 |
| 组织缺口（缺可引用地址） | **成立** | 地址集带来稳定性 + 消除编造边 + 挂载点 |
| 拓扑（层级/横切边）承载定位 | **否证** | anon_shuffled 下崩溃；shuffled 下不能防错层 |
| 模型能**区分**条件 | **成立且很强** | judge 18/18 零漂移 |
| 模型能**标注违规** | **成立** | P1p 3/3 停「化形 + 禁枝 S16」 |
| 模型能执行**否定式约束** | **否证** | gloss / system prompt / 前置事实，三层级全无效 |
| 模型能响应**正向覆盖** | **成立且立即生效** | 注入 S23 后 P3p 3/3 改停，正例不受影响 |
| 整体：树理论能否落地 | **能，且路径比初版想的更宽** | 关键是**覆盖度**；无需后训练 |

**一句话给工程**：别写禁令，写覆盖。建树时先问"这种情形停哪里"，
再让禁枝节点承担"违规标记地址"的角色。

- 无需 pip 安装任何第三方包
- 需要一台**可访问 `note3-prev-api.askdiandian.com`** 的机器 + 一个合法 api_key

## 5. 已知坑（都踩过）

| 坑 | 现象 | 处理 |
|----|------|------|
| **v1 包内 `localize.py` 不可移植** | 硬编码 `/workspace/uploads/cowrite_tree/app`，该路径不存在 → 直接报 FATAL | 用 `localize_v1.py`；旧版仅留作备查 |
| **边未校验 = 模型编边被算作提议** | 第一版 `score_arm` 只查 id 是否越界，不查边是否在声明边表 → tree 臂输出过 `S12—parent—S05`（不存在）、把兄弟写成父子 | 已加 `allowed_edges` 白名单，off-chart 边单列、不计分 |
| **模型会输出 3–4 个节点** | 协议要求 1–2 个，多给会稀释 Jaccard（tree 0.800 → 0.500） | prompt 强制「nodes 恰好 1–2 个」 |
| **`node.parent` 与 `edges` 数组是两套表示** | 26 条 parent 边与 v0 的 9 条边**零重叠** | `compact_trunk`/`build_views` 里显式合并（`trunk_v1_parent_edges.json` 加性并入） |
| **gold 缺失边 → edge_recall 恒 N/A** | demo 锚只有 `gold_node_ids`，无 `gold.edges` | 记为**不可评**，不得当 0；外源锚必须补 `gold.edges` |
| **随机基线口径** | gold=1 的锚若误用 k=2 得 0.074，正确 k=\|gold\| 应为 1/27=0.037 | 以 `check_trunk.py` 的 `k=\|gold\|` 列为准（joint 4.21e-6，不是 1.68e-5） |
| **让模型自填 `rule_check` 会误报** | 正例 P2 3/3、P3 2/3 自填为触发，repair 后正例被改错 | 判定与定位必须**分离为两次独立调用**（`judge.py`） |
| **中文文件名乱码** | Windows 打的 zip 常为 GBK 文件名 | `unzip -O gbk`；已内置自动判定与修复 |
| **parent 边方向约定不一** | `trunk_v1_parent_edges.json` 的 26 条是**子→父**（B01→T01）；若按父→子方向复算编造边，会误判 B 臂 16 条「编造」 | 复算编造边必须用「声明集 = v0 的 9 条 ∪ parent 26 条」原样比对（from,to,kind）三元组 |
| **草稿 gloss 的 top-k 线索截断** | `cocoon_to_branch.py` 的 `top_cues(k=8)` 只留高频线索；BD01 gloss 因此漏掉同族的「元叙述」，导致元叙述条目稳定错停兄弟节点 | 补全 gloss 线索枚举（`gloss_patch_bd01_fullcues.json` 已验证 0→1 修复）；维护规则见茧→枝结论 F3 |
| **exact_set 在 n=1 时是噪声** | 模型稳定输出 2 节点、gold 多为 1 节点，exact 低是粒度不匹配 | 以 hit_any 为主指标；exact/Jaccard 只作辅助，不做单格比较结论 |

## 6. 结果判读纪律（不得违反）

- **node hit 在本轮已天花板**（双臂 10/10），不能再作主度量；改用 Jaccard / 边审计性 / 作者确认率。
- demo 锚（`source: anchor_demo`）是**从 label 反写**的，**不得**作理论主证据。
- 构造探针（`anchors_lit_v1.json`）复杂度**低于真实对话**，只用于机制判别。
- 本包所有数字**不得**写成「理解已达成」「定位已验证」「VERIFY 主表提升」。
- 「ban 生效」只能写成「ban 让模型**标注**违规」，**不得**写成「ban 阻止了停靠」——实测它说了禁令仍照停。

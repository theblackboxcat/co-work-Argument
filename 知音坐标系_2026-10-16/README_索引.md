## 一句话结论（06:55 修订版）

> 这个模型**分得清**（独立判定 18/18）、**能标注违规**（P1p 3/3 停「化形+禁枝」）、
> **也能停对**——只要坐标系里有对应的正向停靠点（注入「字面景物」节点后 P3p 3/3 改停）。
> **真正无效的只有否定式约束**：写"禁止停在 A"，在节点释义 / system prompt / 前置已确认事实

>
> **落地原则：不要写禁令，要写覆盖。** 用正向替代节点覆盖该情形；
> 禁枝（ban）的真实价值是提供**可停靠的违规标记地址**，不是阻止停靠。

> 真相是 trunk 中没有"字面景物"节点可去，是**覆盖缺陷**而非执行缺陷。

## 三件套架构（已实测，可直接用）

```
① 定位臂  judge 之外的独立调用：给坐标系，只输出 {nodes, edges}（不要它自检）
② 校验臂  judge.py：独立调用，看不到①的输出，只判条件是否成立
③ 代码    拿②的结论硬过滤①；违规 → 拒绝 / repair / 交作者
④ 作者    commit（generate ≠ commit 不变）
```

**为什么校验臂必须独立**：让定位臂自填 `rule_check` 会误报——正例 P2 三次自填 `R3=True`、P3 两次自填 `R1=True`，导致正例被 repair 改错。独立后零误报。
